# 학원 랭크 — 개인 순위 기록장과 결과 공유

원장님이 각자 가입하고 본인의 학원·블로그·플레이스 키워드를 입력해 매주 순위를 확인하는 서비스입니다. 원장님이 결과 링크를 공유하면 받은 사람은 로그인 없이 그 결과만 읽을 수 있습니다.

선생님용 회원 목록, 회원별 키워드 열람, 수업 초대 코드, 과제 제출 현황과 관리자 계정은 제공하지 않습니다. 선생님도 원장님이 직접 전달한 링크만 열면 됩니다.

## 원장님 사용 순서

1. **회원가입**: 이름·이메일·비밀번호 입력. 초대 코드 없이 가입합니다.
2. **복구 코드 보관**: 가입 직후 한 번 표시됩니다. 비밀번호를 잊으면 이 코드로 직접 복구합니다.
3. **학원 · 키워드 설정**: 학원명, 블로그 ID, 플레이스 상세 주소와 키워드를 입력합니다.
4. **순위 체크**: 서버 대기열에서 처리하며 창을 닫아도 계속 실행됩니다.
5. **결과 링크 만들고 복사**: 고정된 결과 링크를 카카오톡 등으로 전달합니다.

## 공유 방식

| 방식 | 동작 |
|---|---|
| 이번 기록 공유 | 선택한 체크 결과를 복사해 고정. 이후 순위·설정 변경과 무관하게 유지 |
| 최신 순위판 공유 | 같은 주소에서 가장 최근 성공·일부 성공 결과를 표시 |
| 공유 끄기 | 해당 링크의 로그인 없는 열람을 종료 |
| 새 주소 발급 | 이전 링크를 종료하고 새로운 임의 주소로 공유 |

공유는 기본적으로 꺼져 있습니다. 학원명·선택한 기록의 검색 키워드·순위·수집 시각·결과 문서 링크 등이 공개됩니다. 회원 이메일, 계정 정보, 설정에 입력한 블로그 ID·플레이스 상세 주소, 내부 오류 로그는 공유 API에 포함하지 않습니다. 링크를 전달받은 사람은 로그인 없이 열람하고 다시 전달할 수 있습니다.

각 회원은 본인 기록만 조회·변경할 수 있습니다. 서비스 소유자에게 회원 조회 화면이나 특별한 회원 열람 권한은 부여하지 않습니다. 단, 서비스 소유자는 서버·DB 계정의 권한을 통해 기술적으로 데이터에 접근할 수 있습니다. 이 버전은 운영자 접근까지 차단하는 종단간 암호화 서비스는 아닙니다.

## 비밀번호를 잊었을 때

로그인 화면의 **비밀번호를 잊었어요**에서 이메일·복구 코드·새 비밀번호를 입력합니다. 복구하면 모든 기존 로그인을 종료하고 이전 복구 코드를 폐기한 뒤 새 코드를 표시합니다. 이메일로 재설정 메일을 보내는 서비스는 연결하지 않았습니다. 비밀번호와 복구 코드를 모두 잃으면 운영자에게 복구를 요청하는 흐름은 없습니다.

로그인된 **내 계정** 화면에서는 현재 비밀번호를 확인하고 비밀번호를 변경하거나 복구 코드를 다시 발급할 수 있습니다. 새 코드를 안전한 곳에 보관하세요.

## 로컬 실행

1. Python 3.12 이상 설치. 이 PC에서는 Codex에 포함된 Python도 자동으로 찾습니다.
2. 처음 한 번 `INSTALL.cmd` 실행: 모듈과 Chromium 설치.
3. `START.cmd` 실행: `http://127.0.0.1:8787/` 접속.
4. 일반 **회원가입**으로 시작합니다. 최초 관리자 설정이나 초대 코드가 필요 없습니다.

실행 창을 닫으면 로컬 서비스가 종료됩니다. 로컬 공유 링크는 인터넷에서 접속할 수 없습니다.

## 온라인 배포: 관리형 구성

`render.yaml`은 Render의 웹 서비스 1개와 관리형 PostgreSQL 1개를 연결하는 배포 설정입니다. Python 웹 서버와 수집 프로세스는 웹 서비스 컨테이너 안에서 실행합니다. 데이터는 별도 PostgreSQL에 저장하므로 웹 컨테이너의 임시 디스크에 의존하지 않습니다.

- `Dockerfile.managed`: Chromium과 Python 모듈 설치, 일반 사용자 권한 실행
- `start_production.py`: 웹 서버와 수집 프로세스 실행·종료
- `DATABASE_URL`: Render가 관리형 PostgreSQL에서 주입
- `COOKIE_SECURE=1`: HTTPS 세션 쿠키
- 수집 워커 임대: 배포 시 프로세스가 겹쳐도 동시에 하나만 수집
- 접근 로그 비활성화: 로그에 공유 토큰이 포함된 URL을 남기지 않음

Render에서 리소스를 생성하려면 본인 계정 연결과 비용 확인이 필요합니다. 이 파일을 만들었다고 서버가 생성되거나 결제가 발생하지는 않습니다. 자동 배포는 기본적으로 꺼 두었습니다.

구체적인 GitHub·도메인 연결 순서는 `HAKWONMATE-DEPLOY.md`를 참고하세요. 직접 서버를 관리하려는 경우의 Docker Compose 파일도 남겨두었지만, 현재 권장 배포 경로는 관리형 구성입니다.

## 수집 기준과 제한

- 기존 `rank_check.py` 수집 엔진을 `legacy/`에 복사해 사용하며 원본 프로그램은 변경하지 않았습니다.
- 계정당 학원 1곳, 블로그·플레이스 키워드 각각 최대 40개.
- 계정당 진행 중 작업 1개, 한국 시간 기준 하루 최대 3회.
- 서버 전체에서 수집 1개씩 처리, 키워드 사이 6초 간격.
- 플레이스: 확인한 목록 내 최대 50위.
- 블로그: 광고·플레이스 등을 제외한 통합검색 첫 화면 문서 중 15위. 블로그 전용 탭 순위가 아닙니다.
- 검색 문서 부족·목록 파싱 실패·추가 확인 화면은 `수집 실패`로 기록합니다.
- 실패한 최신 작업은 최신 공유판의 이전 성공 결과를 덮어쓰지 않습니다. 공유 페이지의 수집 시각으로 기준을 확인합니다.
- 키워드가 많거나 사용자가 몰리면 대기시간이 길어집니다. 시험 운영에서 처리량을 확인한 뒤 운영 규모를 정하세요.

## 저장과 백업

- 로컬: `data/rank.sqlite3`. DB 파일을 복사할 때는 앱 종료 후 복사하거나 SQLite backup API를 사용하세요.
- 관리형: `DATABASE_URL`의 PostgreSQL. 호스팅 상품의 백업·복구 범위를 확인하고 정기 복원 테스트가 필요합니다.
- 수집 입력·진단 파일: 작업별 임시 디렉터리에 저장했다가 작업 후 제거합니다. 수집 결과는 DB에 남습니다.
- 계정 비밀번호는 PBKDF2 해시, 세션·복구 코드는 SHA-256 해시로 저장합니다.
- 이전 버전 SQLite의 계정·기록은 유지합니다. 이전 관리자 역할도 특별한 권한 없이 개인 계정으로만 사용할 수 있습니다. 이전 과제 제출 URL은 새 개인 공유 모델로 자동 이전하지 않습니다.
- SQLite에서 PostgreSQL로 실제 기록을 옮기는 자동 이전 도구는 포함하지 않았습니다. 실제 데이터가 있다면 백업 후 별도 이전 작업이 필요합니다.
